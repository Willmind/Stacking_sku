# 装柜码垛术语约定

- 状态：现行
- 最后确认：2026-07-29
- 阅读对象：产品、业务、开发、测试
- 产品可读：是

本文档统一算法、2D/3D 可视化、坐标表和测试中的码垛业务语言。机器人坐标的完整定义见 [`business/coordinate-system.md`](business/coordinate-system.md)。

## 坐标口径

讨论用户可见结果时，使用机器人车厢坐标系：

- 观察者站在柜门处，望向车厢内部的角件端。
- 原点是观察者所见角件端内壁的左下角。
- 从角件端向柜门推进时，`X` 从 `0` 变为绝对值越来越大的负数。
- 横跨车厢内部时，`Y` 使用非正坐标。
- `Z` 从地面向上递增。

讨论算法实现时，必须明确说“内部坐标”：

- 内部 `position.x`：柜长方向，从角件端向柜门递增。
- 内部 `position.y`：柜宽方向。
- 内部 `position.z`：柜高方向。
- 机器人坐标表的 `X/Y/Z` 不能直接等同于内部字段，必须经过 `src/core/boxCoordinates.ts` 换算。

## 核心术语

### 总ID

“总ID”表示整柜纸箱的实际装载先后顺序：

```text
总ID = sequenceIndex + 1
```

总ID必须唯一、连续并从 `1` 开始。2D/3D 进度、纸箱选择、坐标表和 CSV 都应使用同一总ID，不允许各自重新生成顺序。

整柜总体从车厢深处的角件端向柜门推进：

```text
机器人 X：0 -> 更大的负数
```

### 排

“排”表示沿车厢长度方向推进时的一组装载截面。当前坐标表按内部 `position.x` 的不同起始位置划分所属排：

- 角件端第一排为 `1`。
- 从角件端向柜门推进时，所属排递增。
- 在机器人坐标中表现为 `X` 从 `0` 走向更大的负数。

历史文档中可能把同一概念称为“面”。现行界面和 CSV 统一使用“所属排”。

### 层

“层”只表示沿高度方向 `Z` 的堆叠层：

- 地面第一层为 `1`。
- 同一排内从下向上递增。
- 不使用“层”描述柜宽方向或柜长方向的分组。

算法存在明确 `stackIndex` 时：

```text
所属层 = stackIndex + 1
```

缺少 `stackIndex` 时，才根据不同 `Z` 起始坐标计算层号。

### 排内ID

“排内ID”表示纸箱在所属排中的局部顺序：

- 每一排都从 `1` 重新开始。
- 按总ID出现顺序递增。
- 业务意图是从观察者看到的左侧到右侧、从下到上完成当前排。
- 如果几何位置、2D/3D 播放和总ID顺序不一致，应视为排序缺陷，而不是在坐标导出阶段重新排列。

### 朝向

“朝向”描述纸箱原始长、宽、高分别落在车厢内部哪个方向，例如：

- 长×宽×高
- 宽×长×高
- 长×高×宽

朝向只改变空间占用和姿态角，不改变纸箱原始长、宽、高。六种朝向的 `ABC` 见 [`business/coordinate-system.md`](business/coordinate-system.md)。

## 标准码垛顺序

标准顺序为：

1. 从角件端第一排开始，逐排向柜门推进。
2. 当前排从第一层开始，逐层向上。
3. 同一层内按观察者从柜门望向角件端时看到的左侧到右侧码放。
4. 当前排完成后，才能进入下一排。
5. 总ID保持算法确定的真实装载顺序；坐标导出只读取，不重新定义顺序。

示意：

```text
第 1 排第 1 层 -> 第 1 排第 2 层 -> ... -> 第 1 排完成
第 2 排第 1 层 -> 第 2 排第 2 层 -> ... -> 第 2 排完成
...
柜门端最后一排
```

不应理解为：

```text
整柜第 1 层全部铺完 -> 整柜第 2 层全部铺完
```

也不应理解为：

```text
固定一个宽向位置一直堆高 -> 再处理下一个宽向位置
```

## 起步与宽向压紧约束

任意一排开始时，第一箱必须紧贴集装箱侧壁，禁止从宽向中间位置起垛。

内部坐标判断口径：

- `position.y = 0` 表示贴一侧侧壁。
- `position.y + position.dy = container.width` 表示贴另一侧侧壁。

角件避让可以影响具体坐标，但不应让某一排从宽向中间起步。

同一端面投影内，不同朝向纸箱应互相靠紧；如果柜宽存在余量，余量必须位于外侧柜边，不能夹在不同纸箱组之间。

## 顺序与最终排布

码垛顺序是纸箱的装载先后；最终排布是所有纸箱装完后的空间结果。

只调整总ID或播放顺序时，不应改变：

- 最大装载量。
- 每个纸箱的最终空间位置。
- 占用长度、宽度和高度。
- 角件避让结果。
- 不同朝向纸箱组之间的压紧关系。

如果柜宽余量出现在不同朝向纸箱组之间，属于最终排布错误，需要先修正几何位置，不能仅通过重排总ID掩盖。

## 俯视统计口径

俯视图中的“横向占 29 列 / 竖向占 26 列 / 共 55 列”是最终地面排布统计，不等于所属排数量，也不直接定义总ID。

`40HQ / 488 × 380 × 291 mm / 单 SKU` 的现行基准为：

- 横向占 `29` 列。
- 竖向占 `26` 列。
- 合计 `55` 列。
- 占用宽度 `2332 mm`。
- 宽度余量 `20 mm`。
- 最大装载量 `1349` 箱。

完整基准见 [`business/benchmark-cases.md`](business/benchmark-cases.md)。

## 坐标表口径

每个纸箱输出：

```text
总ID、SKU、长、宽、高、X、Y、Z、A、B、C、所属层、所属排、排内ID、朝向
```

- `总ID`：整柜装载顺序。
- `所属层`：当前纸箱的高度层号。
- `所属排`：从角件端向柜门计算的排号。
- `排内ID`：当前排中按总ID递增的局部编号。
- `XYZ`：纸箱远离柜门面的左下角，不是中心点。
- `ABC`：`Z-Y-X` 欧拉角，单位为度。

## 术语使用建议

- 使用“排”描述从角件端向柜门推进的装载截面。
- 使用“层”描述高度方向堆叠。
- 使用“排内ID”描述当前排内部的局部顺序。
- 使用“总ID”描述整柜实际装载先后。
- 使用“朝向”描述纸箱原始长宽高在车厢中的摆放关系。
- 使用“最终排布”描述装满后的几何位置、装载量和空间占用。
- 提到 `x/y/z` 时明确说明是“内部算法坐标”还是“机器人坐标”。
