# 装柜基准案例

- 状态：现行
- 最后确认：2026-07-29
- 阅读对象：产品、业务、算法、开发、测试
- 产品可读：是

本文档记录修改算法、坐标、渲染或 Worker 链路时不能回退的业务基准。自动化测试是这些数值的最终执行依据。

## 必须保持的两组实际基准

| 纸箱尺寸（长×宽×高） | 柜型   | 最大装载量 | 业务说明                                |
| -------------------- | ------ | ---------: | --------------------------------------- |
| `488 × 380 × 291 mm` | `40HQ` | `1,349` 箱 | 尾部局部补位后，前部角件干涉区域少 1 箱 |
| `488 × 360 × 291 mm` | `40HQ` | `1,403` 箱 | 前空 1 箱，后部满放                     |

对于 `488 × 380 × 291 mm` 案例，还应保持：

- 横向占 `29` 列。
- 竖向占 `26` 列。
- 合计 `55` 列。
- 占用宽度 `2332 mm`。
- 柜宽余量 `20 mm`，且余量位于外侧边缘，不能出现在不同朝向纸箱组之间。

## 修改后的判断方式

- 只修改总ID或展示顺序：装载量、最终空间排布、占用尺寸和角件避让结果都不应变化。
- 修改候选策略或尾部补位：必须重新检查两组装载量，并检查所有纸箱无重叠、无越界、无角件干涉。
- 修改坐标换算：内部装载结果不应变化，只改变面向机器人的输出表达。
- 修改 2D/3D 渲染：渲染数量、选择状态和进度必须与 `sequenceIndex` 一致。

## 自动化覆盖

- 核心数量与几何安全：`tests/packing-core.test.ts`
- 浏览器结果与视图：`tests/packing-e2e.spec.ts`
- 性能基准：`tests/packing-performance.test.ts`
- 批量导入结果：`tests/batch-import.test.ts`

算法、页面或渲染相关改动完成前，优先运行：

```bash
npm run test:unit
npm run test:e2e
npm run build
```

涉及性能路径时额外运行：

```bash
npm run test:perf
```

## 历史数值说明

早期规格和计划中可能出现 `1,340` 箱，这是尾部局部优化之前的历史基准，不是当前验收值。现行基准以本页和当前测试为准。
