# 决策 0001：机器人坐标与纸箱位姿输出

- 状态：已接受
- 日期：2026-07-29
- 影响范围：坐标弹窗、CSV、2D/3D 坐标表达、机器人对接
- 阅读对象：开发、测试；产品需要追溯决策背景时可选读
- 产品可读：可选

## 背景

旧坐标表使用纸箱中心点和另一套展示轴定义，且姿态曾按 `XYZ` 欧拉角表达。机器人实际需要角件端左下角为车厢原点、负向的长度和宽度坐标，以及工业常用的 `ZYX` 姿态表示。

示意图中的坐标轴交点和角件端原点曾被误认为两个不同位置，因此必须用观察视角和业务文字固定原点，而不能只依赖透视图判断。

## 决策

1. 观察者站在柜门处，望向车厢内部的角件端。
2. 原点位于观察者所见角件端内壁的左下角。
3. 从角件端向柜门推进时，机器人 `X` 从 `0` 变为绝对值越来越大的负数。
4. 横跨车厢内部时，机器人 `Y` 使用非正坐标；`Z` 向上为正。
5. 每个纸箱的位置输出其远离柜门面的左下角，不输出中心点。
6. 纸箱自身长、宽、高分别定义为局部 `X/Y/Z`。
7. `A/B/C` 分别表示绕车厢 `Z/Y/X` 轴旋转，采用 `Z-Y-X` 欧拉角顺序和角度制。
8. 总ID继续以算法已有的 `sequenceIndex + 1` 为准。

## 结果

- 旧版“中心点 XYZ”和“XYZ 欧拉角”字段不再是现行业务接口。
- 坐标换算集中在 `src/core/boxCoordinates.ts`，不能分散到 UI 或渲染器中。
- 六种允许朝向必须有确定的规范化 `ABC` 输出。
- 界面、CSV 和自动化测试必须使用同一字段定义。

完整现行规则见 [`../business/coordinate-system.md`](../business/coordinate-system.md)。
